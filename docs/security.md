# Security and Privacy

## Security goals

- Prevent root-owned file creation on the host filesystem without requiring `sudo` or elevated host privileges.
- Protect developer and CI environments from committing secrets, credentials, or local `.env` overrides.
- Ensure generated microservices default to safe, non-privileged configurations with explicit TLS toggles for message
  brokers.
- Verify dependency integrity through Composer validation and locked dependency trees (`composer.lock`).

## Trust boundaries

The boilerplate operates across three primary boundaries:

1. **Host Environment & `.env` Configuration**:
   - `.env.dist` is tracked in Git with non-sensitive example values.
   - `.env` is git-ignored so local project customizations or private registry settings are never committed to the
     boilerplate repository.
2. **Docker Container Isolation (`boilerplate`)**:
   - All PHP, Composer, and third-party vendor binaries run inside the `boilerplate` container with only `./app` bind-
     mounted to `/app`.
   - The container matches the host user's UID and GID (`USER ${HOST_UID}:${HOST_GID}`) at build time so container
     processes run as an unprivileged user rather than `root`.
3. **External Package Registries (Packagist / Git Hosts)**:
   - `docker/Dockerfile` pre-populates `~/.ssh/known_hosts` via `ssh-keyscan -H` for `github.com`, `gitlab.com`, and
     `bitbucket.org` during image build to support authenticated SSH dependency fetching when needed.

## Data classification

| Data Category                     | Classification       | Handling & Protection Rules                              |
|-----------------------------------|----------------------|----------------------------------------------------------|
| `.env.dist` placeholders          | Public Configuration | Safe example values only; committed to Git               |
| Local `.env` overrides            | Local Configuration  | Git-ignored (`/app/` and `.env` in `.gitignore`)         |
| Generated `app/.env` `APP_SECRET` | Development Default  | Generated by Symfony Flex for local dev; not for prod    |
| Generated `RABBITMQ_URL`          | Development Default  | Uses `amqp://guest:guest@rabbitmq:5672` for local dev    |

## Container security and permission model

- **No `sudo` Requirement**: `create-microservice.sh` and the root `Makefile` export `HOST_USER`, `HOST_GROUP`,
  `HOST_UID`, and `HOST_GID` before running `docker compose`. `docker/Dockerfile` creates the matching group and user
  and sets `USER ${HOST_UID}:${HOST_GID}`, ensuring every file created in `./app` is owned by the host user.
- **PHP Runtime Hardening (`docker/image-files/usr/local/etc/php/conf.d/base-custom.ini`)**:
  - `expose_php=off` prevents leaking PHP version headers.
  - `cgi.fix_pathinfo=0` prevents path resolution vulnerabilities.
  - `short_open_tag=0` enforces standard `<?php` tags.
  - `date.timezone = UTC` ensures deterministic timestamp handling across environments.
- **RabbitMQ TLS Support in Generated Services**:
  - Generated microservices configure `roslov_queue.rabbitmq.simple_ssl_context_provider` as the
    `connection_parameters_provider` and `RABBITMQ_SSL_ENABLED` so production environments can enable AMQP over TLS
    without code changes.
